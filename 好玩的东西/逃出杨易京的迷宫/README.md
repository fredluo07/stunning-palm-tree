# 暗影迷宫 / Dark Maze

一个用 **C++17 + OpenGL 3.3 core** 写的第一人称恐怖迷宫游戏，玩法对标《黑暗欺骗》（Dark Deception）：在迷宫里奔跑、收集全部水晶、躲避追猎者，集齐后触发红色警报并逃向传送门。

**界面全中文，自带中文菜单 / HUD / 帮助 / 暂停 / 失败 / 通关结算，自带动态配乐与音效。**

---

## 一、直接运行

双击 **`DarkMaze.exe`**（已用本机 MSVC 编译好，x64）。建议戴耳机。

需要：Windows 10/11、支持 OpenGL 3.3 的显卡驱动（近十年的独显/核显都可以）。

如果启动报错，先跑一次自检：

```
DarkMaze.exe --selftest
```

它会在真实驱动上编译全部着色器、检查 FBO、模拟完整通关流程，并验证鼠标视角方向、键盘/鼠标菜单导航、手电筒在地面与掠射墙面的可见亮度，把结果写到 `selftest_result.txt`，详细日志写到 `darkmaze.log`。看到 `RESULT: PASS` 就说明环境没问题。

## 二、玩法

| 阶段 | 内容 |
|---|---|
| 开场 | 3.6 秒淡入，交代目标 |
| 收集 | 迷宫中散布 **24 枚水晶**，全部收集；HUD 实时显示进度 |
| 追逐 | 最多 **3 只怪物**：BFS 寻路 + 网格射线视线判定 + 巡逻/追击/搜寻/眩晕状态机；冲刺更快、蹲伏更隐蔽 |
| 难度递增 | 收集 1/3 出现第 2 只、2/3 出现第 3 只，速度与感知范围随进度上升 |
| 被抓 | 扣 1 条命（共 3 条），红闪 + 惨叫 + 粒子 + 震动，回起点重生；**水晶保留**，怪物短暂眩晕 |
| 警报 | 集齐后灯光转红、配乐切换为逃脱节奏、紫色传送门开启；传送门位置升起常驻紫色光柱，HUD 常驻显示方位与距离 |
| 逃脱 | 走进传送门通关，结算用时 / 死亡次数 / 评级（S·A·B·C） |

**主动技能**：`Q` 目标感应 —— 收集阶段指出最近未收集水晶的八方位与距离，集齐水晶后自动改为指向紫色传送门；同时在目标位置打出紫色光柱，10 秒冷却。逃脱阶段即使不按 `Q`，HUD 也会常驻显示传送门方位/距离，传送门上方常驻光柱，不会找不到出口。
`Shift` 冲刺消耗体力（8.1 m/s，比怪物快），体力自动恢复。

## 四、自己编译

### 方式 A：一键脚本（推荐，本机已验证）

双击 `build.bat`。脚本通过 `vswhere.exe` 自动定位 Visual Studio，调用 `vcvars64.bat` 后直接用 `cl.exe` 编译，产物为 `DarkMaze.exe`。

### 方式 B：CMake

```bat
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

> 注意：CMake 生成器需要 VS 安装「使用 C++ 的桌面开发」+「C++ CMake 工具」；若 CMake 报 `No CMAKE_CXX_COMPILER could be found`，直接用方式 A。
> MinGW-w64 也可：`cmake -S . -B build -G "MinGW Makefiles"`，链接 `opengl32 gdi32 user32 winmm` 并加 `-mwindows`。

### 依赖

**零第三方库、零外部素材文件。** 只链接 Windows 系统库：`opengl32.lib gdi32.lib user32.lib winmm.lib`。
不需要 GLFW / GLAD / GLEW / GLM / Assimp / FreeType / irrKlang / STB。

## 五、技术要点

- **GL 运行时**：`glcore.h` 自己从 `opengl32.dll` + `wglGetProcAddress` 加载 OpenGL 3.3 函数，用 `wglCreateContextAttribsARB` 创建 core profile 上下文。
- **画面**：程序化石材漫反射贴图 + 由高度场生成的法线贴图（砖缝、污渍、苔痕、血迹）；手电筒聚光 + 最多 8 个动态点光源 + 方向光阴影贴图（3×3 PCF）；指数雾；Bloom（亮度提取 + 两次高斯）；暗角、色差、胶片颗粒、扫描线、心跳屏幕畸变、受伤红闪、追逐血色边缘、屏幕震动。
- **模型**：迷宫网格（墙/地/顶各一套材质、顶点 AO）、水晶、传送门、粒子均程序化生成；**怪物改为 `g.PNG` 图片平面**（见下条）。图片加载失败时自动回退到原先的破损人偶模型。
- **怪物图片 `g.PNG`**：放在 exe 同目录。用 GDI+ `SHCreateMemStream` **按文件内容**解码（你给的这个文件头是 JPEG，扩展名虽是 `.PNG`），转成 32 位纹理；在视图空间展开成面向相机的平面，尺寸随距离透视缩小，仍受深度测试约束会被墙挡住；`MONSTER_FS` 给四边做柔和淡出并略微压暗偏冷，避免白底照片出现生硬方块边。换图只要覆盖同名文件即可，PNG/JPG/BMP 都行，带透明通道的图片也会保留。**没有做色键抠图**——人像照片的背景与主体颜色连续，自动抠图会抠出破碎的洞。编译需链接 `gdiplus.lib shlwapi.lib`（脚本已配好）。
- **中文 UI**：用 GDI 的微软雅黑把中文抗锯齿渲染到 32 位 DIB，转成带 alpha 的纹理并缓存；UI shader 做黑描边与外发光。无需字体文件。
- **音乐/音效**：`waveOut` 四缓冲实时合成。分层动态配乐（低频 drone 拍频 + 金属摩擦 + 风声 + 心跳 + D 小调音序 + 追逐三全音/鼓点 + 逃脱警报），危险度与阶段实时改变节奏；脚步、水晶、吼叫、惨叫、警报、传送门、胜负等音效全部合成。**没有任何 mp3/wav 文件。**
- **手电筒光照**：聚光锥约 53°、`wrap diffuse`(ndl=(N·L+0.42)/1.42) + 7.5 米内的朝向无关散射补光，保证脚下地面、掠射侧墙都不会陷入纯黑；`uAmbient` 提供保底轮廓光。**阴影贴图只用于轻微压暗环境光，绝不乘到手电上**——它是从天顶俯视的正交深度图，天花板会挡在地面之前，乘上去会让地面和大片墙面被判为全阴影（开着手电也全黑）。
- **自检**：`--selftest` 会真的编译 9 个 GLSL 程序、创建 FBO、生成资源，模拟一整局（开场→收集 24 枚→警报→传送门→胜利），并额外验证鼠标视角方向、键盘/鼠标菜单导航、手电光照系数、Q 感应目标切换（水晶→传送门）、`g.PNG` 按内容解码。
- **输入**：键盘由 `WM_KEYDOWN/WM_KEYUP` 消息驱动为主、`GetAsyncKeyState` 兜底；菜单里鼠标移动即悬停高亮，且只有鼠标真的移动过才覆盖键盘选择。

## 六、关于「网上的模型 / 贴图」

你提到可以随便用网上的模型和贴图。这里**没有下载任何第三方素材**，原因有三个：第三方模型的许可与下载链接不稳定、离线工程无法保证资源齐全、加 Assimp/FreeType 会让编译配置变成最容易翻车的一环。场景贴图/几何/音乐全部程序化生成，只有怪物用了你本地提供的 `g.PNG`（按文件内容解码，见第五节）。这样工程依然「解压即编译、双击即玩」，只多一个同目录图片文件。

如果想换成真实素材，替换点很集中：

- **贴图**：`resources.h` 的 `generateStone()` 返回 `TexPair{albedo, normal}`，可仿照 `image.h` 里的 GDI+ 解码器（已支持 PNG/JPG/BMP，按内容识别）把外部图片转成两张纹理，再交给 `uploadTex()`；不需要额外引入 stb_image。
- **模型**：`Renderer::init()` 里的 `makeSphere / makeCrystal / makeTorus` 等替换为自己的 OBJ/glTF 加载结果，填进 `std::vector<Vertex>` 再交给 `makeMesh()`；顶点格式是 `pos3 / normal3 / uv2 / ao1`，已和场景着色器对齐。
- **音乐**：`audio.h` 的 `AudioEngine::fill()` 是合成入口，可以改成读取 PCM 数据混入 `s`；`SfxId` 枚举对应各个事件触发点。

## 八、常见问题

- **黑屏 / 弹窗「无法创建 OpenGL 3.3」**：更新显卡驱动；笔记本请在系统设置里把程序指定为高性能 GPU。
- **没有声音**：程序在无音频设备时会自动静默降级，游戏不受影响；检查系统默认输出设备。
- **着色器报错**：打开 `darkmaze.log`，里面会打印每个着色器的完整编译日志与 GL 版本/显卡型号。
- **窗口太小 / 想全屏**：拖动窗口边框即可缩放，渲染目标会自动重建。
